# speedtest-cli

Консольный скрипт на Node.js, который замеряет скорость скачивания по адресу:
делает 10 запросов подряд, считает среднее время запроса, общий объём и скорость.

Без внешних зависимостей. Нужен Node.js 18 или новее.

## Запуск

```bash
git clone <ссылка-на-репозиторий>
cd speedtest-cli

node src/cli.js <адрес>
```

Пример:

```bash
node src/cli.js https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

Количество запросов можно поменять (по умолчанию 10):

```bash
node src/cli.js <адрес> --count 5
```

## Пример вывода

```
Адрес: https://example.com/big.jpg
Запросов: 10 (последовательно)

[1/10] 4.20 МБ за 912 мс
...
[10/10] 4.20 МБ за 870 мс

--- Итог ---
Запросов:               10
Среднее время запроса:  885 мс
Скачано всего:          42.00 МБ
Скорость скачивания:    37.97 Мбит/с
```

## Единицы измерения

- **Скорость:** мегабиты в секунду (Мбит/с), 1 Мбит/с = 1 000 000 бит/с.
- **Размер:** мегабайты (МБ), 1 МБ = 1 000 000 байт.
- **Время:** миллисекунды (мс).

Скорость считается как `все байты / всё время`, а не как среднее скоростей
отдельных запросов, чтобы быстрые и медленные запросы учитывались по весу.

## Как это работает

- Запросы идут строго последовательно: следующий начинается после того, как предыдущий полностью получен.
- Тело ответа читается потоком и не хранится в памяти, поэтому можно проверять большие файлы.
- Время каждого запроса считается от начала запроса до последнего полученного байта.
- Таймаут одного запроса: 30 секунд.
- Если сервер ответил ошибкой (не 2xx) или запрос оборвался, скрипт печатает ошибку и завершается с кодом 1.

## Ограничения

- `fetch` сам распаковывает gzip/br, поэтому для сжимаемого контента (HTML, JSON) считаются распакованные байты.
  Для замера канала лучше брать уже сжатые файлы: картинки, архивы, видео.
- Первый запрос обычно медленнее из-за установки соединения (DNS, TLS), поэтому его время включено в среднее.

## Структура

```
src/
  cli.js         точка входа: собирает всё вместе
  args.js        разбор и проверка аргументов (чистая функция)
  downloader.js  скачивание одного URL (единственный код с сетью)
  benchmark.js   N последовательных запросов
  stats.js       подсчёт среднего и скорости (чистая функция)
  format.js      оформление вывода
test/            тесты
```

## Как я использовал ИИ

Я использовал ИИ как помощника, а решения принимал сам. Сначала поставил задачу и ограничения: без зависимостей, запросы по очереди, понятные единицы. Архитектуру тоже выбрал сам: маленькие модули, сеть только в одном файле, остальное чистые функции, чтобы тесты шли без сети. Стек взял современный и встроенный в Node: fetch, потоки, AbortSignal.timeout, parseArgs и node --test. Первую версию кода и тестов написал ИИ, а я всё прочитал, запустил и поправил. Отдельно руками проверил скорость, ошибку 404, зависший сервер и неверный --count.

## Что бы я улучшил, будь больше времени

Первым делом убрал бы влияние первого запроса: он включает DNS и TLS и занижает среднее, поэтому сделал бы прогрев соединения. Потом добавил бы min, max и медиану вместо одного среднего. Дальше параллельные запросы через флаг, чтобы мерить полную скорость канала, и вывод в JSON для скриптов. Ещё добавил бы повтор запроса при сетевой ошибке, настраиваемый таймаут и CI, который гоняет npm test.
